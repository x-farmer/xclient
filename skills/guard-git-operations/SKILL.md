# Guard Git Operations

Read `docs/standards/git-workflow.md` first. GitHub cannot enforce branch
protection for these private repositories, so two local layers enforce the
workflow on developer machines.

## When to Use This Skill

- At the start of a task, to confirm the guards are installed in this checkout.
- When a guard blocks a command, to understand why and which compliant command
  to use instead.

## Pre-Push Hook

`skills/guard-git-operations/hooks/pre-push` runs for every `git push`, from any
tool or from a human, once `core.hooksPath` points at it. It rejects:

- pushes to `dev` or `main`;
- a pushed branch that does not contain the last fetched `origin/dev`;
- merge commits between `origin/dev` and the pushed commit; and
- in a repository with submodules, a gitlink that no remote branch of that
  component contains.

Check and install from the repository root:

```bash
python3 skills/guard-git-operations/scripts/install-git-hooks.py --check
python3 skills/guard-git-operations/scripts/install-git-hooks.py
```

The installer configures this checkout and every initialized submodule with the
relative hooks path, so each checkout uses its own copy of the hook. A
submodule checked out at a revision that predates the hook runs no hook until
it is updated. The installer refuses to replace a different `core.hooksPath` or
to hide existing custom hooks unless `--force` is given. `core.hooksPath` is
shared by every worktree of the same repository.

## Agent Shell-Command Policy

`.cursor/hooks.json` (`beforeShellExecution`) and `.claude/settings.json`
(`PreToolUse` for Bash) call
`skills/guard-git-operations/scripts/guard-command.py`. These adapters are
generated by the root harness synchronization tool; do not edit them by hand.
The policy:

- **Denied:**
  - `gh pr merge` against `x-farmer/x-farmer-dev`, and merging any pull request
    through `gh api`;
  - `gh pr merge` without both `--rebase` and `--match-head-commit`, or with
    `--squash`, `--merge`, or `--admin`;
  - `gh pr create` without `--base dev`, and `gh pr edit` to another base;
  - `git push` with `--force`, `-f`, a `+` refspec, a lease that does not name
    both the ref and its expected SHA, `--no-verify`, `--mirror`, `--all`, no
    explicit refspec, or `dev`/`main` as the destination;
  - overriding `core.hooksPath` with `git -c`;
  - `git merge` without `--ff-only`, `git pull` without `--ff-only` or
    `--rebase`, and `git stash` other than `list` or `show`; and
  - `git commit` or `git rebase` on `dev`, `main`, or a detached HEAD when no
    rebase, merge, or cherry-pick is in progress.
- **Requires confirmation:** `git reset --hard`, `git clean -f`, deleting a
  branch, and discarding paths with `git checkout` or `git restore`.

The policy reads only the command text and local repository state; command
substitution and similar shell tricks can evade it. The pre-push hook is the
backstop for every push. Codex has no equivalent shell hook and relies on the
pre-push hook and `AGENTS.md`.

When a guard blocks a command, do not look for a bypass. Use the compliant path
it names, usually the exact command emitted by
`skills/prepare-feature-branch/scripts/prepare-feature-branch.py`.
